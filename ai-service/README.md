# SlopeGuard AI Service (Phase 6: Machine Learning Prototype)

**Module:** `ai-service`  
**Model Architecture:** Scikit-Learn `RandomForestClassifier` Baseline  
**Governance Status:** **`DEMO_NOT_VALIDATED`**  
**Classification:** Experimental Prototype (Not certified for real-world disaster warnings)

The `ai-service` is an independent, lightweight Python microservice designed for landslide risk estimation. It models the interaction between static topographic susceptibility (slope gradient, lithology, elevation) and transient hydrometeorological triggers (antecedent 24h/72h precipitation).

---

## 1. Important Geotechnical & Governance Disclaimers

> [!CAUTION]
> **Prototype Safety & Ethics Statement:**
> - **DEMO STATUS ONLY:** The current model is trained exclusively on synthetic test fixtures (`data/synthetic_fixtures.csv`). It has **not** been calibrated against historical field landslide registries.
> - **NOT A CIVIL PROTECTION WARNING SYSTEM:** Predictions generated by this service are provisional mathematical heuristics. They must **never** be used as the sole basis for evacuation directives or structural safety decisions.
> - **ABSENCE OF RECORD != ABSENCE OF HAZARD:** Rural hill tracts often lack field reporting. A location without historical landslide records cannot be presumed safe.
> - **FEATURE IMPORTANCE != CAUSALITY:** Tree-based Gini importance scores represent decision split frequencies within the model, not geotechnical causality.
> - **STATIC SUSCEPTIBILITY VS DYNAMIC TRIGGER:** A steep slope has persistent high static susceptibility, but requires a dynamic trigger (such as prolonged precipitation or seismicity) to initiate slope failure.

## 4. Training the Model

Train the baseline Random Forest classifier using the data preparation and temporal validation pipeline:

```powershell
# Run from ai-service root
python src/train.py

# Alternatively as a module
python -m src.train
```

### Training Pipeline Safeguards:
1. **Schema & Integrity Validation:** Validates physical bounds (e.g., `rainfall_72h_mm >= rainfall_24h_mm`, `slope_deg in [0, 90]`).
2. **Leakage Prevention:** Chronological temporal train/test split (75/25) guarantees no future data trains past events.
3. **Multi-Metric Evaluation:** Evaluates precision, recall, F1-score, confusion matrix, ROC-AUC, and PR-AUC. Never evaluates accuracy alone.
4. **Reproducibility:** Seed fixed at `RANDOM_SEED = 42`.

## 8. Transitioning to Validated Production Models

To advance this pipeline from `DEMO_NOT_VALIDATED` to `VALIDATED_HISTORICAL`:
1. Obtain historical landslide polygons/points from the **Geological Survey of India (GSI) Bhukosh portal**.
2. Align each landslide initiation timestamp with historical gridded rainfall reanalysis from **India Meteorological Department (IMD)** or **Open-Meteo Historical Weather API**.
3. Sample non-landslide stable control sites within identical lithological formations to establish realistic background class distributions.
4. Place validated records in `data/verified_historical/` with `is_synthetic = false`.
5. Execute calibrated probability scoring using Platt scaling or Isotonic Regression before defining operational alert thresholds.
